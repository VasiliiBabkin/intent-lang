## Реально реализовано

- Полноценный неизменяемый текст в типизированной AST, состояниях, вычисляемых значениях, действиях, правилах, тестах и JSON CLI. Нет конкатенации, неявных преобразований или исполнения пользовательского кода.
- Общий строгий escape-aware разбор значений и меток. `true`/`false` внутри строки не меняются. Неверные escape-последовательности, незакрытые строки, неподдерживаемые формы Python и суррогаты отклоняются с диагностикой.
- Лимит 1024 Unicode scalar values в Python, JavaScript и JVM; emoji вне BMP считается одним scalar value. Нет усечения, нормализации, изменения регистра или обрезки пробелов принятого текста.
- `input` выводит тип редактора из состояния. Web получает textarea с доступными ошибками, Android — Compose OutlinedTextField. Принятый снимок защищён от неправильного ввода и частичных изменений.
- Сохранение проверяет тип/длину/суррогаты каждого поля и правила всего восстановленного снимка. Kotlin-функции перехода/редактирования/восстановления общие для Compose-обработчиков и JVM-тестов.
- Рабочий [text_profile.sdr](../examples/text_profile.sdr): имя Guest, Unicode-переименование, проверяемый ввод, производные флаги, сохранение и атомарный отказ смешанного действия. [Hostile-string fixture](../tests/fixtures/text_escaping.sdr) проверяет данные, похожие на HTML/JS/Kotlin-код.
- [Справочник](LANGUAGE_0_10_TEXT.md), Quick Start, roadmap и changelog обновлены. Метаданные разработки — `0.10.0.dev0`; полного выпуска 0.10 нет. Опубликованный тег 0.9.0a1 указывает на `261ed75a42aafbae8186891a6f3f920d220b58c0` и не изменяется.

## Ошибки, найденные испытаниями

1. Глобальная замена булевых ключевых слов повреждала бы текст: теперь она выполняется только вне литералов.
2. Regex-метки не поддерживали безопасно кавычки и escapes: используется общий строгий декодер.
3. Web сворачивал пробелы/переводы строк при отображении: вывод теперь сохраняет пробельное оформление.
4. UTF-16 `.length` не соответствует scalar limit: введён одинаковый подсчёт и отказ для непарных суррогатов на границах ввода и хранения.
5. Android-значения нельзя преобразовывать через `str(value).lower()`: строковый регистр сохранён, данные экранируются для Kotlin.
6. JVM теперь проверяет тот же сгенерированный путь принятия состояния, который вызывают callbacks, вместо отдельной тестовой реализации действий.
7. CLI ограничивает чтение исходника числом символов и сохраняет строгую проверку UTF-8.

## Ограничения и решения

- Нет локального `/dev/kvm` и подключённого ADB-устройства. JVM/сборка/Lint не являются проверкой Compose UI, реального перезапуска процесса, IME или поворота экрана. Прежние результаты Android 16 относятся к прежнему APK.
- Escape-sensitive метки 0.9 требуют удвоить буквальный backslash при переходе на общую грамматику. Эта граница совместимости явно описана и проверена; все опубликованные примеры 0.9 покрыты регрессией.
- HTML textarea нормализует CR/CRLF черновика в LF. Модель, исходные литералы, действия и сохранённые значения сохраняют scalar sequence. Оба поведения проверены браузерным тестом.
- Нет шифрования, коллекций, записей, навигации, тем или полного task-manager milestone. Android-примеры разделяют application ID; при переключении следует очистить данные. Среда компиляции не является сертифицированным sandbox.
- GitHub Release и тег не создаются, PyPI не используется. Это проверяемый промежуточный шаг, а не объявление всей версии 0.10 завершённой.

# Переход на 0.10.0rc2 и откат — кандидат не опубликован

Пакет и CLI называются **sedrava**. Опубликованная база — **0.9.0a1 на GitHub**,
а не вымышленная `sedrava==0.9` из PyPI. Исторический `intent-lng` — другой пакет.
Комплекты rc1/rc2 — артефакты Actions, не публикации индекса. Сохраните комплект rc1.

1. Запишите путь старого интерпретатора, `sedrava --version` и
   `python -m pip show sedrava`. Сделайте копии проектов и данных, сохраните старое
   окружение. Проверяйте RC на копиях; миграций форматов нет.
2. Скачайте комплект RC2 **для точного проверенного SHA**. Сверьте внешний digest
   ZIP Actions, затем все SHA256SUMS и инвентарь манифеста по
   [процедуре](RC_PUBLISHING.md). Сохраните комплект, квитанцию и контрольные суммы.
3. Установите проверенный wheel в отдельное окружение:

```sh
python -m venv .venv-sedrava-rc2
. .venv-sedrava-rc2/bin/activate
# Windows PowerShell: .venv-sedrava-rc2\Scripts\Activate.ps1
python -m pip install --no-index /absolute/path/to/verified-kit/sedrava-0.10.0rc2-py3-none-any.whl
sedrava --version
# sedrava 0.10.0rc2
python -m pip show sedrava
sedrava check /path/to/copied/project.sdr
sedrava test /path/to/copied/project.sdr
sedrava run /path/to/copied/project.sdr
sedrava build web /path/to/copied/project.sdr --output build/rc2-web/index.html
sedrava build android /path/to/copied/project.sdr --output build/rc2-android
```

4. Проверьте примеры `reference_09`, `text_profile`, `task_manager`,
   `task_manager_navigation` из `sys.prefix/share/sedrava/examples` и реальные UI.
5. Для отката интерпретатора выполните `deactivate`, активируйте **неизменённое**
   старое окружение, проверьте версию и исходный проект командами check/test.
   0.9 не понимает новый синтаксис 0.10. При необходимости создайте ещё одно
   окружение с проверенным wheel `sedrava-0.9.0a1-py3-none-any.whl` из GitHub
   v0.9.0a1; SHA-256:
   `b6e3a54df2355803fa1e47b5e7e849ba242bfd6437f226534db13aabc4210339`.
   Сверьте и release SHA256SUMS. Автоматическая проверка использует именно этот
   опубликованный wheel и проверяет сохранность проектов и прежнее поведение.

## Обновление Android rc1 → rc2

Нужны прежние application ID **и сертификат подписи**, versionCode
**10001 → 10002**. Код этого PR не меняет ID. Для собственного приложения
сохраняйте явный `--application-id`: ID по умолчанию зависит от точного названия.
Используйте исходный ключ; отладочные ключи разных машин/запусков могут отличаться.
Не удаляйте приложение и не очищайте данные ради обновления. На тестовом устройстве
обновите совместимым APK с тем же ключом через `adb install -r /path/to/rc2.apk`,
затем проверьте данные, холодный запуск, навигацию и ошибки.

CI собирает неизменяемый исходник rc1
`6ddae99fc837d67b465285f629d9f5a2ec52e870` и RC2 одним отладочным ключом.
В rc1 создаётся задача через UI, **затем** выполняется настоящая установка -r,
проверяются ID/сертификат/код, значения, устойчивые ID и повторный холодный запуск.
Отдельные обновления rc1→rc2 начинаются с повреждённых/несовместимых данных и
подтверждают видимый отказ и сохранность оригинала после перезапуска. Независимые
сценарии подготавливают чистую старую базу **до** ввода данных; между вводом и
обновлением нет uninstall/clear. Это не замена обновления чистой установкой и не
изменение исходного комплекта rc1. Старый приватный debug-ключ другого runner
не предполагается доступным.

Откат APK отличается от отката Python: Android обычно запрещает уменьшение
versionCode. `adb install -d` не гарантирует совместимость данных. Сохраняйте
старые APK/исходники/данные и не удаляйте единственную копию ради downgrade.
Старый 0.9 ID `org.sedrava.generated` отличается от новых хешированных ID;
используйте его только для прежнего приложения с прежним ключом и совместимыми
данными. Другой ID означает независимое приложение, а не обновление.

## Данные

[Контракт совместимости](COMPATIBILITY_010.md) описывает точный fingerprint,
непостоянные состояния, правила, старый скалярный формат и ключи хранилищ.
Автоматического переноса или понижения формата нет. Перед ручным сбросом сделайте
копию отвергнутого оригинала; RC2 защищает его от перезаписи. Новые изменения могут
оставаться в памяти. Смена Web origin/пути/названия выбирает другое хранилище;
query/fragment ключ не меняют. Нет автоматического переноса между приложениями,
согласования одновременных записей, шифрования и гарантии при отключении питания.
